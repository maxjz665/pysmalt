# Определение авторства текста — запуск

Модуль `research.authorship`: атрибуция авторства по синтаксическим признакам.

## Linux

Smoke (без dump):

```
bash run_smoke_authorship.sh
```

Полные корпуса 5x8/5x7/7x6 — положить `smalt.sql.20260115.070144.gz` рядом с `manage.py`, затем:

```
bash run_full_authorship.sh
```

Оба скрипта ставят `.venv`, грузят корпус, поднимают worker и сервер.
После запуска открыть http://127.0.0.1:8000/research/authorship/

## Windows

```
bash run_smoke_authorship.bat
bash run_full_authorship.bat
```

Docker (только smoke): `docker compose up --build`

## Worker

Кнопки Profile/ML создают эксперимент со статусом `queued`. Без запущенного
worker'а задачи не выполняются. Скрипты запуска поднимают его сами, вручную:

```
python manage.py run_authorship_worker --settings=shower.settings.demo
```

Worker берёт по одной задаче (n_jobs=1, рассчитано на 1 ядро).
Боевой systemd-сервис — в `service/` (`smalt-authorship-app.*`, по аналогии с tree/ngram).

## Корпуса

- smoke — 3 автора × 4 текста, встроен, для проверки запуска.
- 5x8 / 5x7 / 7x6 — из dump SMALT
`smalt.sql.20260115.070144.gz`

Загрузка и запуск вручную:

```
python manage.py load_authorship_demo --corpus=all \
    --source-sql=smalt.sql.20260115.070144.gz --no-extract --settings=shower.settings.demo

python manage.py run_authorship --list-name="Authorship corpus 5x8" \
    --method=profile --extract-features --queue --settings=shower.settings.demo
```

## Атрибуция фрагментов

`/research/authorship/attribute/fragments/` — текст бьётся на фрагменты, для
каждого показывается ближайший авторский профиль. Только profile-метод; на
коротких фрагментах результат менее устойчив.

## Проверка

```
python manage.py check --settings=shower.settings.demo
python manage.py test research.authorship --settings=shower.settings.demo
```
